# IMP-001 · CI/CD no GitHub Actions

- Etapa: melhoria (protege as Etapas 1 a 3)
- Status: concluída
- Data: 08/11/2026
- Jira: [PMF4-30](https://akiravkax.atlassian.net/browse/PMF4-30)

## Objetivo
Nenhum merge na `main` sem lint, testes e contrato de dados verdes; e, a cada merge, o pipeline de
monitoramento roda do zero com os dados reais e entrega os resultados. Critério do card: um PR que
quebra o contrato fica vermelho no GitHub.

## Conceito por trás (didático)
**CI** (integração contínua) é o porteiro do merge: toda mudança passa pelas mesmas checagens
automáticas antes de entrar. **CD** (entrega contínua) é o que acontece depois que entrou: o
sistema é montado e entregue sem passo manual. Analogia: o CI é a inspeção de cada peça na linha de
montagem; o CD é o carro saindo da fábrica pronto para ser dirigido, a cada lote de peças aprovadas.

Contrato de dados no CI é o que o PDF chama de "integrar os contratos ao fluxo de deploy": a regra
de qualidade não é só um script que alguém lembra de rodar, é uma porta que o código não atravessa.

## Escopo
- Dentro: `ci.yml` (qualidade e contrato), `pipeline.yml` (monitoramento a cada merge),
  `scripts/check_evidence.py`, selos no README.
- Fora: proteção de branch exigindo o check (configuração do GitHub, feita pelo Akira); deploy do
  modelo em produção (não existe API nesta fase).

## Critérios de aceite (verificáveis)
- [x] PR para a `main` roda ruff, pytest e o portão de contrato.
- [x] Portão vermelho quando o contrato é afrouxado (mutação: idade mínima 18 para 10, exit 1).
- [x] Portão verde com o contrato atual, sem sobrescrever a evidência versionada.
- [x] Lotes regerados batem com os hashes de `reports/drift/`.
- [x] Merge na `main` roda o pipeline semanal e publica artefatos, sem `failure_cases.csv`.
- [x] Limites calibrados reproduzíveis (recalibração deu arquivo idêntico).

## Como validar de verdade
```
uv run python scripts/check_evidence.py      # exit 0 com o contrato atual
```
No GitHub: a aba Actions do PR mostra os jobs "Lint e testes" e "Contrato de dados e evidência".

## Resultado
- Local: portão aprovado (Produção-base passa, corrompido barrado com as 5 regras esperadas, 3 hashes
  iguais). Com a mutação, portão reprovado e exit 1; arquivo restaurado depois.
- O exit code sozinho não pegaria a mutação: o lote continuou barrado pelas outras 4 regras.
- Execução no GitHub: registrada no PR do card.

## Pendência do Akira
Em Settings > Branches, exigir os checks "Lint e testes" e "Contrato de dados e evidência" na regra
da `main`. Sem isso, o CI avisa mas não impede o merge.
